name: rea-design
description: Reverse engineer a supplied image, post, banner or graphic into an evidence-backed design breakdown and an actionable reconstruction plan. Use for visual style, composition, typography, overlapping elements and inferred layers.
---

# rea-design

Treat the source as a flattened observation, not as the original editable document. Do not claim hidden pixels, exact fonts, blend modes, asset provenance or layer boundaries as facts without evidence. A vision-capable agent is required for semantic interpretation; the CLI provides measurements and views, not automatic layer extraction.

1. Establish the source and requested outcome: analysis, editable recreation, or style transfer. Inspect the actual image at full size and run `rea-design inspect <image> --out <output>` when available. Run `rea-design ocr` and `rea-design segment` if the optional vision dependencies are installed. Use a visually chosen `--rect x y width height` for a GrabCut subject candidate. Read the JSON and inspect overlays, masks, grid, edges and relevant crops. Preserve the source; use a new output folder for each run. If a capability is unavailable, use equivalent tools and state what was not measured.
   When the documented FCN model is available, run `rea-design semantic`, then `rea-design scene` with the semantic and OCR JSON. The model recognizes only 20 fixed classes; connected components can split one subject or merge subjects. Treat mask intersections as possible overlaps, not evidence of front-to-back order. Review `scene.json`, correct text, colors, masks and `render_order` as needed. `rea-design export-svg` creates editable text and raster cutouts over an inpainted raster background; inspect the rendered result, particularly text and missing hidden pixels. It is not recovery of source layers.
2. Work from canvas to regions to details. Map visual hierarchy, alignment, negative space and reading order. Identify visible elements and estimate their pixel bounding boxes and normalized coordinates (x/width, y/height, width/width, height/height). Check OCR against the image even at high confidence. Color components can split or merge objects; GrabCut returns a candidate foreground, not a semantic class. Inspect masks for missing details and contamination. Check crops at overlaps and edges before deciding front-to-back order. A crop, mask or edge map is not proof of independent layers.
   For orthogonal poster grids, run `rea-design geometry <image> --out <directory>` and inspect `geometry-overlay.png`. Import `geometry.json` with `scene --geometry` to create independently editable SVG rectangles. Lines, opacity and fully bounded solid cells are proposals. Keep `source_bbox` as the position in the input raster when moving a detection by changing `bbox`. For partially covered photography, use a clean aligned plate if one is available.
   For a large title, run `rea-design typography <image> --ocr <ocr.json> --out <directory>` and review its line boxes and transcriptions. Import the title with `scene --typography`. Edit `lines[].text` and export again to remeasure a replacement, using `--title-font <local font>` when available. Check the rendered title against the neighboring text and alignment guides. The suggested family and weight are visual approximations.
   For an object named by the user, try `rea-design segment-text <image> --prompt "<object description>" --models-dir <models> --out <directory>` when the optional Grounding DINO and SAM weights are present. Inspect `grounded-overlay.png` and `cutout.png` before importing `grounded.json` with `scene --grounded`. The detector proposes coordinates itself. A `no-match` result or visibly incorrect pixels require review or one of the manual-mask workflows.
   For a complete multi-object reconstruction, try `rea-design assemble` with one `--prompt` per object. Review the generated `scene.json`: small masks mostly contained in larger objects produce a suggested foreground relation, while ambiguous intersections remain unknown. The export groups the grid and any detected technical text beside the title. If a foreground object must move and an aligned unobstructed patch exists, provide it as `--repair-plate`. Re-export using `--move <layer-id> <dx> <dy>` or repeated `--title-line` to test edits against the same scene.
   To carry a reviewed subject into the SVG, pass `scene --grabcut <segments.json>` after `segment --rect`, or add `--mask <label> <full-canvas-mask.png>`. Rerun the scene with `--replace-mask <layer-id> <corrected-mask.png>` to keep its ID and recompute intersections. When a clean generated or supplied photo is available, align it to the reference, check that the masks follow its edges, and pass it to `export-svg --clean-plate`. Use a separate `--background-plate` if moving the object reveals artifacts and an aligned background is available. Add reviewed grid lines and cells to the scene as `rect` layers with `bbox`, `fill` and optional `opacity`, then place their IDs in `render_order`. Render the SVG after changing the text, moving the cutout or recoloring a shape to verify the edit.
3. Write `DESIGN.md` using [the breakdown contract](references/design-format.md). Separate measured facts, visual observations and hypotheses; cite filenames or coordinates for each major claim. Record alternatives and confidence where occlusion, transparency or effects create ambiguity. Describe typography by visible characteristics; suggest candidates only as unverified. Record actual text only when legible, marking uncertain text.
4. Provide an ordered build recipe: canvas, background, subjects, geometry, text, masks, compositing, lighting and texture as appropriate. For each element describe editable representation, placement, effect parameters or plausible ranges, and dependencies. Distinguish reusable style from logos, copy and source assets. Never promise to recover hidden originals from one raster image.
5. If reconstruction is requested, use available editing tools to create it and render a preview. When the canvases match, run `rea-design compare <reference> <render> --out <comparison>` and inspect overlay and difference plus the images themselves. Iterate on the largest visible discrepancies: composition, overlap and typography before small texture. Pixel error is alignment-sensitive, not a perceptual score. Report remaining differences and unavailable capabilities. Only claim a completed recreation when an artifact was actually created and checked.

Use other installed skills or tools when they concretely help with OCR, segmentation, font search, image editing, or a requested output format. Verify their output visually. Prefer licensed or user-provided assets when recreating; note substitutions and avoid suggesting that a visual match proves original provenance.
